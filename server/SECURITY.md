# Security and publication review

This is a sanitized preparation candidate, not a security certification or guarantee of no personal data. Review source, fixtures, metadata, dependencies and local output before public release. No repository history, recordings, logs, credentials, TLS material, device settings, screenshots, generated build products or private reports should be committed.

Bearer token possession authorizes the associated device. TLS and hostname validation are required in the real app; explicit loopback-only HTTP may be used behind a trusted TLS proxy (see docs/PROXY.md). Tokens are hashed in bridge device records but plaintext device settings remain highly sensitive. SQLite contains transcripts and ACP session metadata; MP3s may remain after turns. Existing private databases may also retain historical integration records. Use private directories, restrictive umask and full-disk/host security. Back up/revoke credentials appropriately.

Provider credentials remain server-side. The direct-model runtime uses only its configured OpenAI-compatible endpoint/token; there is no Hermes pool, account rotation or model fallback. HTTP upstream transport is restricted to loopback; remote endpoints require HTTPS. Never point offline tests at a real model/account. Remote prompts, agent replies and model output are untrusted data. The direct-model backend has no built-in tools and denies tool/function calls. The four inherited bridge dispatchers and their approval/dispatch/backup helpers are removed. The legacy authenticated confirmation endpoint always denies authorization.

ACP delegates to an agent with its own privileges, MCP integrations and skills; denial of ACP client permission requests is not an agent sandbox. Cancellation does not undo agent actions. Interrupted or uncertain turns are not automatically retried; durable session binding prevents prompt replay, without claiming distributed exactly-once execution or verified physical outcomes. See [ACP trust boundaries](docs/ACP.md).

`python tools/privacy_scan.py` checks general sensitive-data classes, forbidden files and unexpected endpoints without printing matched values. PUBLICATION-MANIFEST.txt explicitly lists shipped files. Missing/unlisted files, forbidden generated directories, hidden/ignored additions, unreadable entries, symlinks and binaries fail the publication-input check; .gitignore never excludes input. Remove build/cache output physically before scanning or packaging. The automated hygiene regression scans a copy of Git-tracked source so local private runtime state and dependencies are not publication inputs; review staged files before committing. Review manifest changes manually; listing a file is not approval of its contents. Secret/PII detection remains heuristic, not proof. Independent manual review and a privately supplied literal list remain necessary for names, calendar/device identifiers and unknown secret formats. For private literals supplied independently, use `--literal-file /absolute/private/file` with one value per line; this file must remain outside the repository. Never embed a personal blacklist in tests, scanner source, reports, or Git history. The scanner does not read credentials automatically and never contacts services.

No public vulnerability-report address has been established. Before publication, create an owner-controlled reporting channel and review the MIT scope and separate third-party obligations in LICENSE-STATUS.md. MIT selection is not publication approval.

# Security and publication review

This is a sanitized preparation candidate, not a security certification or guarantee of no personal data. Review source, fixtures, metadata, dependencies and local output before public release. No repository history, recordings, logs, credentials, TLS material, device settings, screenshots, generated build products or private reports should be committed.

Bearer token possession authorizes the associated device. TLS and hostname validation are required in the real app; loopback HTTP exists only in synthetic native tests. Tokens are hashed in bridge device records but plaintext device settings remain highly sensitive. SQLite contains transcripts and action metadata; MP3s/rollback exports may remain after turns. Use private directories, restrictive umask and full-disk/host security. Back up/revoke credentials appropriately.

Provider credentials remain server-side. The Codex pool can rotate or persist authentication state when runtime is deliberately used; never point tests at an actual account. Remote prompts, note/event contents and model output are untrusted data. Tool arguments are constrained, yet enabled HA tokens and TV scripts have broad impact; no promise of sandboxing or mandatory user confirmation is made.

Cancellation does not undo already dispatched actions. Interrupted or uncertain mutations are not automatically retried. Claims reduce duplicate dispatch, not a distributed exactly-once guarantee. A successful webhook/service response is not physical device success. One shared mutation slot per turn applies across HA, notes, calendar and TV. Any second mutation claim in the same turn is rejected, including a different HA action.

`python tools/privacy_scan.py` checks general sensitive-data classes, forbidden files and unexpected endpoints without printing matched values. PUBLICATION-MANIFEST.txt explicitly lists shipped files. Missing/unlisted files, forbidden generated directories, hidden/ignored additions, unreadable entries, symlinks and binaries fail the publication-input check; .gitignore never excludes input. Remove build/cache output physically before scanning or packaging. Review manifest changes manually; listing a file is not approval of its contents. Secret/PII detection remains heuristic, not proof. Independent manual review and a privately supplied literal list remain necessary for names, calendar/device identifiers and unknown secret formats. For private literals supplied independently, use `--literal-file /absolute/private/file` with one value per line; this file must remain outside the repository. Never embed a personal blacklist in tests, scanner source, reports, or Git history. The scanner does not read credentials automatically and never contacts services.

No public vulnerability-report address has been established. Before publication, create an owner-controlled reporting channel and review the MIT scope and separate third-party obligations in LICENSE-STATUS.md. MIT selection is not publication approval.
